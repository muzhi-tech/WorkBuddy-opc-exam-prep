# 第9课 题库（专家中心与模型配置）

## 单选题

**Q1.** 在 WorkBuddy 中，「专家」的本质是以下哪一项？
- A. 单个工具函数，负责完成某个具体操作
- B. 独立人设 + 方法论 + 工具链，相当于该岗位的资深从业者
- C. 多个 Agent 组成的协作团队
- D. 一套按 Token 计费的模型接入方案

> **答案：B**｜**解析**：专家 = 独立人设 + 方法论 + 工具链；A 是 Skill，C 是专家团，D 是 Token Plan。｜**考点**：一、专家与专家团的定义

**Q2.** 关于专家团的积分消耗，下列说法正确的是？
- A. 与单个专家相同
- B. 比单个专家低，因为并行执行更高效
- C. 是单个专家的数倍，因为多 Agent 在串行或并行运行
- D. 完全免费，不消耗积分

> **答案：C**｜**解析**：专家团涉及多个智能体同时工作，消耗是单专家的数倍，首次召唤会有积分提醒。｜**考点**：一、专家 VS 专家团对比

**Q3.** 召唤专家/专家团的正确流程顺序是？
- A. 选择 → 打开 → 描述任务 → 召唤
- B. 打开 → 选择 → 召唤 → 描述任务
- C. 打开 → 召唤 → 选择 → 描述任务
- D. 描述任务 → 打开 → 选择 → 召唤

> **答案：B**｜**解析**：四步为打开（左侧边栏进专家中心）→ 选择（看卡片三要点）→ 召唤（确认积分提醒）→ 描述任务。｜**考点**：二、召唤流程

**Q4.** 在专家中心选择专家时，课程建议看卡片上的哪三要点？
- A. 模型名称、API 地址、端口号
- B. 能力介绍、擅长领域、任务示例
- C. 积分价格、响应速度、上下文长度
- D. 创建时间、使用次数、用户评分

> **答案：B**｜**解析**：选择专家看能力介绍（核心背景）、擅长领域（覆盖方向）、任务示例（能解决的问题类型）。｜**考点**：二、召唤流程

**Q5.** 「帮我从法律角度审一下这份合同」，最适合使用？
- A. Skill
- B. 灵感
- C. 召唤专家
- D. 启动专家团

> **答案：C**｜**解析**：单点专业问题找专家（领域方法论）；Skill 解决「做某件事」，专家团解决复杂项目交付。｜**考点**：四、三者辨析

**Q6.** Multi-Agent 协作流程中，「将子任务分配给合适的专家 Agent」之前的一步是？
- A. 用户描述高层次目标
- B. 团长理解需求，拆解为子任务
- C. 各专家 Agent 并行或串行执行
- D. 团长收集输出并整合交付物

> **答案：B**｜**解析**：5 步顺序：描述目标 → 团长拆解 → 分配子任务 → 各 Agent 执行 → 团长整合。｜**考点**：五、Multi-Agent 协作架构

**Q7.** 关于深度思考（Thinking）模式，下列说法正确的是？
- A. 直接生成回答，速度快、Token 消耗低
- B. 先进行内部推理链（Chain of Thought）再输出结论，复杂任务准确率显著提升
- C. 只适合日常对话和简单任务
- D. 所有内置模型都默认开启 Thinking 模式

> **答案：B**｜**解析**：Thinking 模式先 CoT 推理再输出，适合复杂逻辑/数学/代码调试，代价是时间更长、Token 更高；A、C 描述的是标准推理。｜**考点**：六、标准推理 VS Thinking

**Q8.** 需要频繁工具调用的 Agent 场景，课程推荐选择哪类模型？
- A. 混元系列模型
- B. GLM 系列或 MiniMax 系列模型
- C. DeepSeek 系列模型
- D. 任意模型，工具调用稳定性无差别

> **答案：B**｜**解析**：Agent 场景选 GLM 或 MiniMax 系列，工具调用最稳定；混元系列强在推理，多模态选 GLM/Kimi。｜**考点**：七、模型选择策略

**Q9.** 使用「自定义 API」方式接入模型时，用户需要手动提供的是？
- A. URL 地址和模型列表
- B. 能力标记配置
- C. API key
- D. model.json 配置文件

> **答案：C**｜**解析**：选好厂商后 URL、模型列表、能力标记全部自动填充，只需补一个 API key，全程不改配置文件。｜**考点**：八、方式三自定义 API

**Q10.** Ollama 本地部署方案中，Ollama 默认监听的端口是？
- A. 8080
- B. 443
- C. 11434
- D. 3000

> **答案：C**｜**解析**：Ollama 默认监听 11434 端口，WorkBuddy 通过兼容 OpenAI 协议的接口自动对接。｜**考点**：八、方式四 Ollama

**Q11.** 关于 Token Plan，下列说法错误的是？
- A. 使用腾讯云账号体系完成鉴权和计费
- B. 按 Token 用量计费，适合团队使用
- C. 需要单独管理每家模型厂商的 API key
- D. 接入后可使用混元、MiniMax、Kimi、GLM 等多个模型

> **答案：C**｜**解析**：Token Plan 由腾讯云统一账号鉴权，不需要单独管理各家厂商的 API key。｜**考点**：八、方式一 Token Plan

## 多选题

**Q12.** 下列关于专家与专家团对比的说法，正确的有？（多选）
- A. 专家是单 Agent 架构，专家团是 Multi-Agent 架构
- B. 专家是顺序处理，专家团是串行或并行执行后再整合
- C. 专家团由团长自动拆解任务、分配并整合交付
- D. 专家团的积分消耗低于单个专家

> **答案：ABC**｜**解析**：D 错误，专家团消耗是单专家的数倍。｜**考点**：一、专家 VS 专家团对比

**Q13.** 自定义模型接入的四种方式包括？（多选）
- A. Token Plan
- B. Coding Plan
- C. 自定义 API
- D. Ollama 本地部署

> **答案：ABCD**｜**解析**：四种方式为 Token Plan、Coding Plan、自定义 API、Ollama，覆盖从云端到本地全场景。｜**考点**：八、四种接入方式

**Q14.** 下列关于 Skill、专家、专家团三者辨析的说法，正确的有？（多选）
- A. Skill 是工具能力，解决「让 AI 做某件事」
- B. 专家是 AI 顾问，相当于工具加经验，解决「用什么方法做」
- C. 专家团解决「复杂项目如何交付」

> **答案：ABC**｜**解析**：D 错误，积分消耗 Skill 最低、专家中等、专家团最高。｜**考点**：四、三者辨析

**Q15.** 关于自定义模型可视化管理界面，下列说法正确的有？（多选）

- B. 保存即生效，配置自动持久化
- C. 工具调用、图片输入等能力标记自动识别写入
- D. 旧的 model.json 配置文件不再兼容，老用户必须迁移

> **答案：ABC**｜**解析**：D 错误，model.json 仍然兼容，老用户无需迁移。｜**考点**：八、可视化管理界面

**Q16.** 课程给出的 5 条最佳实践中，包括以下哪些？（多选）
- A. 不知道选什么模型时优先用 Auto

## 判断题

**Q17.** 首次召唤专家团时，系统会弹出积分提醒，且 AI 生成的法律、医疗、财务内容可直接作为最终决策依据。（ ）

> **答案：错误**｜**解析**：积分提醒属实，但 AI 生成内容仅供参考、不构成决策建议，法律/医疗/财务领域最终判断需人工确认。｜**考点**：二、召唤流程

**Q18.** 在已经完成的项目中输入创建提示词，AI 可以结合当前项目上下文创建出更贴合实际工作场景的专属专家。（ ）

> **答案：正确**｜**解析**：这是创建专属专家的更便捷方式，能更精准地沉淀工作经验，创建后立即出现在「我的专家」列表中。｜**考点**：三、我的专家

**Q19.** 除主流厂商预设配置外，其他厂商的自定义模型目前仅支持 OpenAI 兼容协议 API。（ ）

> **答案：正确**｜**解析**：自定义 API 支持主流厂商预设；其他厂商目前仅支持 OpenAI 兼容协议 API。｜**考点**：八、方式三自定义 API

**Q20.** Ollama 方案的推理在本地 GPU 或 CPU 上完成，数据不出本机，但需要持续联网才能使用。（ ）

> **答案：错误**｜**解析**：Ollama 零成本、离线可用、隐私有保障，尤其适合政企内网和机舱离线场景，无需联网。｜**考点**：八、方式四 Ollama

## 场景应用题

**Q21.** 某政企客户计划在内网环境部署 WorkBuddy，对数据隐私要求极高，且部分使用场景（如出差机舱中）完全离线。同时该客户的市场团队想用 AI 完成一套完整的新品营销方案（含策略、广告、商务合作、收益预测）。请分别说明：（1）模型接入应选哪种方式，为什么；（2）营销方案任务应召唤专家还是专家团，为什么。

> **参考答案**：（1）选 Ollama 本地部署。本地安装启动 Ollama（默认 11434 端口）后在模型配置中选 Ollama 作为提供商，系统通过兼容 OpenAI 协议的接口自动对接；核心优势是数据不出本机，推理在本地 GPU/CPU 完成，零成本、离线可用，正好匹配内网+离线+隐私敏感场景。（2）应召唤专家团。完整营销方案是复杂大任务，需要多角色协作交付：团长先确认画像再拆解子任务，分配给策略、广告、商务、收益分析等多个专家 Agent 并行执行，最后整合为统一交付物；单点问题才用专家。
> **解析**：模型选型抓「隐私优先/离线 → Ollama」；专家与专家团选择抓「单点问题用专家，复杂大任务用专家团」。｜**考点**：八、四种方式选型；一、专家 VS 专家团；五、Multi-Agent 协作架构
