# 第5课 题库（连接器）

## 单选题

**Q1.** 连接器在 WorkBuddy 中的定位是（ ）
- A. AI 直连外部服务的桥梁，解决「AI 能拿到什么」
- B. 本地能力包，解决「AI 会做什么」
- C. AI 与外部服务之间的通信标准
- D. 预定义的提示词模板集合

> **答案：A**｜**解析**：连接器是桥梁/管道，负责取数据；「AI 会做什么」是技能，通信标准是 MCP 协议。｜**考点**：一、连接器是什么 / 二、三者关系

**Q2.** 课程中把 MCP 协议类比为（ ）
- A. 酒店房卡
- B. 餐厅点菜单和 USB-C 接口标准
- C. 一根具体的数据线
- D. 厨房

> **答案：B**｜**解析**：MCP 是 AI 世界的 USB-C，也是点菜单；具体数据线类比的是连接器；房卡类比的是 OAuth 令牌。｜**考点**：三、MCP 协议原理

**Q3.** MCP 的全称及开源方是（ ）
- A. Model Control Protocol，腾讯开源
- B. Model Context Protocol，Anthropic 开源
- C. Multi-Channel Protocol，OpenAI 开源
- D. Model Connector Protocol，Anthropic 开源

> **答案：B**｜**解析**：MCP = Model Context Protocol，模型上下文协议，由 Anthropic 开源。｜**考点**：三、MCP 协议原理

**Q4.** 在 MCP 架构中，Client 和 Server 分别指（ ）
- A. Client 是外部服务，Server 是 WorkBuddy
- B. Client 是 WorkBuddy（发起请求），Server 是外部服务（提供数据）
- C. Client 是授权服务器，Server 是资源服务器
- D. Client 是用户手机，Server 是 WorkBuddy

> **答案：B**｜**解析**：WorkBuddy 作为 Client 发起请求，邮箱、文档等外部服务作为 Server 提供数据。｜**考点**：三、MCP 协议原理

**Q5.** 关于 OAuth 2.0 授权，下列说法正确的是（ ）
- A. WorkBuddy 需要保存用户的邮箱密码才能读取邮件
- B. WorkBuddy 拿到的是 access token，永远不知道用户密码
- C. 授权一旦完成就无法撤销
- D. 授权时必须授予全部权限，不能选择性关闭

> **答案：B**｜**解析**：OAuth 不传密码只传令牌；授权可随时在源站撤销；权限遵循最小权限原则可单独关闭。｜**考点**：四、OAuth 授权流程与安全要点

**Q6.** 在 OAuth 的四个角色中，「真正存数据的地方（如邮箱服务器）」是（ ）
- A. 资源拥有者
- B. 客户端
- C. 授权服务器
- D. 资源服务器

> **答案：D**｜**解析**：资源服务器是真正存数据的一方；授权服务器负责发令牌（房卡）。｜**考点**：四、OAuth 授权流程与安全要点

**Q7.** 连接 QQ 邮箱时，手机端列出的四项申请权限是（ ）
- A. 获取账号信息、读取邮件、发送邮件、删除邮件（可选）
- B. 读取邮件、发送邮件、删除邮件、修改密码
- C. 获取账号信息、读取通讯录、读取邮件、发送邮件
- D. 读取邮件、发送邮件、创建日程、删除邮件

> **答案：A**｜**解析**：四项权限为获取账号信息、读取邮件、发送邮件、删除邮件（可选），其中删除邮件可单独关闭，体现最小权限原则。｜**考点**：六、连接 QQ 邮箱

**Q8.** 判断连接器是否连接成功的视觉标识是（ ）
- A. 卡片变成蓝色
- B. 卡片旁出现绿色圆点
- C. 卡片上出现对勾图标
- D. 卡片自动置顶

> **答案：B**｜**解析**：绿色圆点 = 已连接；加号 = 未连接，点击发起授权流程。｜**考点**：五、内置连接器入口 / 六、QQ 邮箱

**Q9.** 连接腾讯乐享时可选择的登录方式是（ ）
- A. 仅微信扫码
- B. 仅手机号验证码
- C. 微信扫码或手机号验证码，二选一
- D. 邮箱账号密码登录

> **答案：C**｜**解析**：腾讯乐享提供微信扫码和手机号验证两种登录方式，任选其一；QQ 邮箱才是扫码授权。｜**考点**：七、连接腾讯乐享

**Q10.** 关于自定义 MCP 连接器的配置文件 mcp.json，下列说法正确的是（ ）
- A. 保存后需要重启 WorkBuddy 才能生效
- B. 最外层对象是 `servers`，每个 key 是服务地址
- C. token、API key 等敏感信息应放在 `env` 字段，避免硬编码
- D. `type: http` 表示本地启动的服务

> **答案：C**｜**解析**：敏感信息放 env 运行时注入；保存即时生效无需重启；最外层是 `mcpServers`；`http` 表示远程服务，`stdio` 才是本地启动。｜**考点**：八、自定义 MCP 连接器

## 多选题

**Q11.** 连接器这座「桥」能做的四件事包括（ ）
- A. 数据查询
- B. 服务调用
- C. 文件管理
- D. 消息通知

> **答案：ABCD**｜**解析**：四大能力为数据查询、服务调用、文件管理、消息通知，底层全部基于 MCP 协议。｜**考点**：一、连接器是什么

**Q12.** MCP Server 能向 AI 暴露的三类能力是（ ）
- A. Tools（调用函数，如发邮件）
- B. Resources（读取资源，如邮件内容）
- C. Prompts（预定义提示词模板）
- D. Models（切换底层大模型）

> **答案：ABC**｜**解析**：三类能力是 Tools、Resources、Prompts，不包括模型切换。｜**考点**：三、MCP 协议原理

**Q13.** 下列属于课程提到的腾讯系内置连接器的有（ ）
- A. QQ 邮箱
- B. 腾讯乐享
- C. 腾讯会议、企业微信、TAPD、微云
- D. Notion、GitHub

> **答案：ABC**｜**解析**：Notion、GitHub 属于第三方连接器，不是腾讯系。｜**考点**：五、内置连接器概览

**Q14.** 关于断开连接器（解绑），下列说法正确的有（ ）
- A. 可在 WorkBuddy 连接器详情管理界面点「解绑」
- B. 可在第三方平台（如 QQ 邮箱 App 的应用授权里）撤销授权
- C. 两种方式效果一样，都是解除绑定关系
- D. 解绑会同时删除你在原平台的数据

> **答案：ABC**｜**解析**：解绑不删除原平台数据，只切断 WorkBuddy 与平台的连接；想重用再走一遍授权流程即可。｜**考点**：九、断开连接与安全排查

## 判断题

**Q15.** 连接器和技能是替代关系：装了连接器就不再需要技能。（ ）
> **答案：错误**｜**解析**：二者是互补关系——连接器负责拿到数据，技能负责把数据加工成结果，各司其职。｜**考点**：二、三者关系

**Q16.** 在 MCP 的两种传输方式中，stdio 用于远程服务调用，HTTP 用于本地进程通信。（ ）
> **答案：错误**｜**解析**：说反了。stdio（标准输入输出）用于本地进程通信；HTTP 用于远程服务调用。｜**考点**：三、MCP 协议原理

**Q17.** 自定义 MCP 连接器只能接入 WorkBuddy 内置列表中的服务。（ ）
> **答案：错误**｜**解析**：只要服务方实现了 MCP Server 端协议，所有 MCP 协议的服务都可通过自定义连接器接入，不限于内置列表。｜**考点**：八、自定义 MCP 连接器

**Q18.** 修改 mcp.json 配置并保存后，改动即时生效，不需要重启 WorkBuddy。（ ）
> **答案：正确**｜**解析**：课程明确说明保存后改动即时生效，无需重启；但不保存则不生效。｜**考点**：八、自定义 MCP 连接器

## 场景应用题

**Q19.** 你所在公司有一套内部 OA 系统，WorkBuddy 内置连接器列表里没有它，但 OA 团队已实现 MCP Server 端协议并提供了服务地址和 API Key。请说明如何把这套 OA 接入 WorkBuddy，以及接入时的安全注意事项。
> **参考答案**：路径：左侧边栏「专家」→「连接器」选项卡 → 右上角「自定义连接器」→ 打开 MCP 服务管理弹窗 → 点「配置 MCP」编辑 mcp.json：在 `mcpServers` 下新增一个服务，远程服务填 `type: http`、`url`（OA 的 MCP 服务地址），API Key 写入 `env` 字段（不要硬编码在 url 或 headers 明文里、不要提交代码库），保存后即时生效无需重启。也可通过 MCP Hub 粘贴工具链接自动配置，再点「信任授权」。安全注意：使用本人账号授权、企业敏感数据接入前确认合规审批、建议月度检查连接状态、不需要时设 `disabled` 或解绑。｜**解析**：考查自定义连接器的入口、mcp.json 字段含义与五条安全注意事项的综合运用。｜**考点**：八、自定义 MCP 连接器 / 九、安全排查

**Q20.** 你换了一部新手机，担心旧手机上已授权给 WorkBuddy 的 QQ 邮箱连接存在风险，希望彻底切断授权。请给出两种操作方式的具体路径，并说明解绑后原邮箱数据是否会受影响。
> **参考答案**：方式一（WorkBuddy 端）：连接器管理页找到 QQ 邮箱卡片 → 点右侧进入详情管理界面 → 点「解绑」→ 确认弹窗确认。方式二（QQ 邮箱端）：手机 QQ 邮箱 App → 右下角「设置」→「账号」→「安全管理」→「登录设备和授权码」→「应用授权」→ 找到 WorkBuddy 授权记录 → 「撤销」。两种方式效果一样，都是解除绑定；解绑不会删除 QQ 邮箱里的任何数据，只是切断 WorkBuddy 与邮箱的连接，以后想用重新走一遍扫码授权流程即可。｜**解析**：考查两种解绑路径（尤其 App 内的完整路径）以及「解绑不删原平台数据」这一关键提醒。｜**考点**：九、断开连接与安全排查
