# 第3课 题库（助理连接配置）

## 单选题

**Q1.** 关于 WorkBuddy 助理的本质，下列说法正确的是？
- A. 在手机上直接运行 AI，替代电脑完成工作
- B. 用手机远程驱动电脑上的 WorkBuddy，调用电脑上的本地资源执行任务
- C. 把电脑上的文件同步到手机，用手机 AI App 处理
- D. 一个独立于 WorkBuddy 的云端机器人服务

> **答案：B**｜**解析**：助理的核心是用手机遥控电脑上的 AI，因为文件、代码环境、技能和连接器都在电脑上；它不是在手机上跑 AI。**考点**：助理的定义与通信原理

**Q2.** 助理任务与普通任务在工作目录上的区别是？
- A. 助理任务可以随意切换工作目录
- B. 助理任务默认使用系统设置的默认工作空间路径（用户主目录下 `workbuddy` 目录下的 `claw` 文件夹）
- C. 助理任务的工作目录固定在 C 盘根目录，不可修改
- D. 两者工作目录机制完全相同

> **答案：B**｜**解析**：助理使用默认工作空间存储路径（`workbuddy/claw`），可在系统设置中修改且不影响已有数据；普通任务可随便切换目录。**考点**：助理与普通任务的区别

**Q3.** 关于助理任务的会话与上下文管理，下列说法正确的是？
- A. 助理支持同时开多个会话并行执行
- B. 助理不支持手动清空上下文
- C. 助理只支持一个会话，且可设置超时自动清理会话、清空上下文
- D. 助理的上下文会自动无限累积，无任何清理手段

> **答案：C**｜**解析**：助理单会话不并行（避免冲突、顺序执行）；两者都支持手动 `/clear`，助理额外提供可选的超时自动清理机制。**考点**：助理与普通任务的区别

**Q4.** 消息能从手机到达家里电脑上的 WorkBuddy，依赖的架构是？
- A. 手机与电脑通过固定公网 IP 直连
- B. 手机 → 腾讯云中转 → 电脑上的 WorkBuddy 三级架构
- C. 手机和电脑在同一局域网内广播
- D. 手机通过蓝牙近场连接电脑

> **答案：B**｜**解析**：手机和电脑都在 NAT 后面互相找不到对方，腾讯云中转服务器作为中间人，双方都能主动连它。**考点**：助理的定义与通信原理

**Q5.** 助理能做到发消息「秒回」，主要依赖的技术是？
- A. HTTP 短轮询，每秒问一次云端
- B. 短信网关转发
- C. WebSocket 长连接，建立后双方可随时互推消息
- D. 邮件异步投递

> **答案：C**｜**解析**：HTTP 是问一次答一次，WebSocket 建立连接后双向随时推送，无需每次重新握手；配合心跳保活和自动重连。**考点**：助理的定义与通信原理

**Q6.** 使用助理的四个前提条件中，课程特别强调「最常见的问题」是？
- A. 电脑没开机
- B. 电脑休眠导致断网
- C. WorkBuddy 版本过低
- D. 手机没开流量

> **答案：B**｜**解析**：休眠会断网，是四个前提里最常见的问题，所以 WorkBuddy 提供防休眠开关建议打开。**考点**：助理的定义与通信原理

**Q7.** 企微渠道中 EncodingAESKey 的作用是？
- A. 验证消息发送者身份，防伪造
- B. 对消息内容做 AES-CBC 加密（再 Base64 编码），防窃听
- C. 作为企微管理员的登录密码
- D. 生成 Webhook URL 的种子参数

> **答案：B**｜**解析**：防伪造靠 Token 签名验签（Token+时间戳+随机数做 SHA-1）；EncodingAESKey 负责内容加密，截获者只能看到乱码。**考点**：安全机制

**Q8.** 关于企业微信助理两种接入模式，下列说法错误的是？
- A. 长连接模式无需公网 IP 和域名
- B. URL 回调模式需要公网可达的 URL
- C. 长连接模式需要向运营商申请固定公网 IP
- D. 不确定选哪个时应直接选长连接

> **答案：C**｜**解析**：长连接是客户端主动外联，不需要公网 IP——「长连接需要公网 IP」正是课程点名的常见误区；需要公网 IP 的是 URL 回调。**考点**：企微两种接入模式

**Q9.** 下列渠道中，属于凭据型渠道的是？
- A. 微信助理
- B. 微信小程序
- C. 微信客服号
- D. QQ

> **答案：D**｜**解析**：扫码型是微信助理、小程序、客服号和企微长连接扫码模式；凭据型是元宝派、QQ、企微 URL 回调。**考点**：六大渠道总览

**Q10.** 微信家族三个渠道（微信助理、小程序、客服号）的关键差异在于？
- A. 配置难度不同
- B. 只有微信小程序支持任务产物同步到手机
- C. 只有客服号需要凭据
- D. 只有微信助理能发文字消息

> **答案：B**｜**解析**：三个都是一颗星扫码零凭据；产物同步是小程序独有能力，微信助理和客服号均不支持。**考点**：渠道三·微信家族对比

**Q11.** QQ 接入与元宝派接入的关键差异是？
- A. QQ 不需要 App ID 和 App Secret
- B. QQ 没有双端确认环节，注册成功直接能用
- C. 元宝派要求 QQ 账号实名认证
- D. QQ 必须使用 URL 回调模式

> **答案：B**｜**解析**：QQ 三步注册即用；元宝派有双端确认（还需在元宝 App 点「我已操作」）。两者都是 App ID + App Secret 凭据型。**考点**：渠道五·QQ 接入

**Q12.** 在 QQ 开放平台创建机器人失败，最可能的前置原因是？
- A. WorkBuddy 版本低于 V4.5
- B. QQ 账号未完成实名认证
- C. 电脑没有打开防休眠开关
- D. 没有管理员权限

> **答案：B**｜**解析**：实名认证是 QQ 开放平台的硬性要求，未实名连机器人都创建不了；管理员权限是企微的要求，不是 QQ 的。**考点**：渠道五·QQ 接入

## 多选题

**Q13.** 关于助理与普通任务的区别，下列说法正确的有？（ ）
- A. 助理默认使用固定的工作空间路径 `workbuddy/claw`
- B. 助理只支持一个会话，不能并行
- C. 助理可以设置超时自动清理会话上下文
- D. 助理任务只能在手机端发起，主界面无法创建

> **答案：ABC**｜**解析**：助理任务在主界面也能创建，只是典型用法是远程场景，D 错误。**考点**：助理与普通任务的区别

**Q14.** 通用排查四步法的正确顺序包括下列哪些步骤？（ ）
- A. 检查电脑开机、WorkBuddy 在运行、助理服务已开启
- B. 核对助理设置页面对应渠道是否显示「已绑定/已连接」
- C. 凭据型渠道检查凭据是否复制错、带空格、失效
- D. 检查电脑能否访问外网、有无代理 VPN 干扰

> **答案：ABCD**｜**解析**：四步法的完整内容，且顺序递进：先环境、再绑定状态、再凭据、最后网络。**考点**：通用排查四步法

**Q15.** 绑定成功但发消息没响应，课程列出的高频原因包括？（ ）
- A. 电脑休眠，助理服务停止
- B. WorkBuddy 被退出
- C. 绑定状态异常，需解绑后重新绑定
- D. 其他设备占用绑定，新绑定把旧的顶掉

> **答案：ABCD**｜**解析**：四个原因按频率从高到低排列，其中电脑休眠和 WorkBuddy 没开是最高频的两个。**考点**：三个高频问题

**Q16.** 关于企微 URL 回调模式，下列说法正确的有？（ ）
- A. 需要配置 Token 和 EncodingAESKey 两个凭据
- B. 注册成功后 WorkBuddy 会显示 Webhook URL，需回填到企微后台「接收消息 URL」
- C. Webhook URL 泄露后他人可伪造消息推送到你的系统
- D. 适合没有公网 IP 的家庭网络场景

> **答案：ABC**｜**解析**：URL 回调需要公网可达的 URL，这正是它的最大门槛，家庭网络应选长连接，D 错误。**考点**：企微 URL 回调模式

## 判断题

**Q17.** 企微长连接模式需要配置公网可达的 URL，而 URL 回调模式不需要。（ ）

> **答案：错误**｜**解析**：恰好相反——长连接是客户端主动外联，无需公网 IP；URL 回调才需要公网可达的 URL。**考点**：企微两种接入模式

**Q18.** QQ 的 App Secret 关闭页面再进入会显示为星号无法查看原文，所以看到后要第一时间复制保存。（ ）

> **答案：正确**｜**解析**：Secret 不支持明文保存，二次查看会失效变星号，课程要求第一时间保存到记事本或密码管理器，且注意不带首尾空格。**考点**：渠道五·QQ 接入

**Q19.** 微信助理、小程序、客服号三个扫码型渠道都需要用户手动配置 Token 和 AES Key。（ ）

> **答案：错误**｜**解析**：Token 和 AES Key 只存在于凭据型渠道（企微 URL 回调）；扫码型渠道的安全机制由平台底层自动完成，不需要也不能手动配置。**考点**：安全机制

**Q20.** 使用微信小程序的「云端工作」模式可以访问并发送电脑本地的文件。（ ）

> **答案：错误**｜**解析**：云端工作模式在远程沙箱执行，沙箱里没有本地文件；访问电脑本地文件必须用「连接电脑」模式。**考点**：渠道二·微信小程序

## 场景应用题

**Q21.** 小王按教程完成了微信助理扫码绑定，卡片显示绿色「已绑定」。但他在微信里给 ClawBot 发消息，等了十分钟都没有任何回复。请按课程的方法论说明他应该如何排查。

> **参考答案**：按通用排查四步法递进排查。第一步先查最可能的环境问题：确认电脑没休眠（最高频原因，休眠后助理服务停止，唤醒后等几秒会自动重连）、WorkBuddy 是否在运行、助理服务是否已开启，建议打开防休眠开关。第二步回助理设置页面核对绑定状态是否仍显示「已绑定」，状态异常就解绑后重新扫码绑定。第三步微信助理是扫码型渠道无凭据，可跳过凭据检查，但要确认是否在其他设备登录同一微信绑定过助理把当前绑定顶掉了（若有，退出微信重新登录再绑定）。第四步再查网络：电脑能否访问外网、有无代理或 VPN 干扰、WiFi 是否稳定。**解析**：绑定成功但无响应最高频的两个原因是电脑休眠和 WorkBuddy 没开，先查这两件；四步法强调递进顺序，不要一上来就查网络。**考点**：通用排查四步法 + 高频问题二

**Q22.** 某公司 IT 要求所有员工的助理消息必须走企业统一网关以便审计，管理员小李正在配置企业微信助理，但在「接收消息 URL」保存时一直提示验证失败。请说明小李应选择的接入模式、完整配置流程，以及验证失败时的排查方向。

> **参考答案**：因公司有统一网关和审计要求，应选 URL 回调模式（长连接不支持审计，不满足要求）。配置四步：①企微管理后台机器人详情页 → API 配置 → 选「使用 URL 回调」；②Token 和 EncodingAESKey 右侧点「随机获取」，生成后立即复制保存（关闭页面后需重新生成）；③WorkBuddy → 助理设置 → 企微助理集成 → 配置 → 切到「使用 URL 回调」标签 → 粘贴两个凭据 → 注册 → 复制页面显示的 Webhook URL；④回企微后台「接收消息 URL」粘贴 Webhook URL 并保存。验证失败查三项：WorkBuddy 是否在正常运行（注册和验证时需在线）；Token 和 EncodingAESKey 两边是否一致（注意复制时首尾空格）；Webhook URL 是否完整复制无遗漏。**解析**：URL 回调只在统一网关、限制 WebSocket、安全审计三种场景考虑；验证失败的三项检查是课程明确给出的内容。**考点**：企微 URL 回调模式
