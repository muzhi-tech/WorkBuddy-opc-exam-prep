# 第2课 考点笔记（任务创建与结果管理）

## 0. 课程定位

- 主线：写任务描述 → 给上下文 → 推进对话 → 验收产物 → 沉淀工作空间；从「知道/看懂」升级为「动手实操」。
- 完成标准五条 checklist：
  1. 5 分钟内写出含目标、上下文、输出格式的完整任务描述；
  2. 能为任务挂载至少两种上下文（如本地文档+参考链接）；
  3. 任务进行中至少做一次有效追问；
  4. 在右侧产物区完成预览、下载、分享；
  5. 把任务保存到命名规范的工作空间。
- 前置依赖：已安装并完成微信扫码登录；认得新建任务栏、任务列表、右侧结果区；说清 Ask / Craft / Plan 三模式差异。

## 1. 任务描述的黄金法则（四块基本功）

### 1.1 明确目标与验收标准

- 核心原则：**好的任务描述，描述的是终点不是路线**。
- 过程式需求反例：「帮我看看这份合同」；终点式需求正例：「请审阅这份合同，列出所有对乙方不利的条款，并给出修改建议」。
- 验收标准 = 把「产物什么样我才满意」翻译进任务描述；铁律：不写验收标准，WorkBuddy 只能按平均水准交付。
- 常见验收维度四类：**数量**（如五条改进建议）、**结构**（如每类含问题描述、频次、典型原话三个字段）、**长度**（如不超过 800 字）、**标准**（如风格正式、面向客户、不用术语）。

### 1.2 提供必要上下文（四类）

自问：「一个完全不认识你、不熟悉项目的同事，光凭这句话能不能干活？」

1. **任务发布者身份**：如「我是产品经理，报告给销售老板看」。
2. **前因后果**：如「上周客户大会的反馈，下周一例会要用」。
3. **约束条件**：本质是负面清单，告诉 WorkBuddy 哪些事不能做（如不涉及价格、不点名客户、保留原话引用）。
4. **专有名词**：内部代号、产品名、术语缩写要解释清楚或挂术语表。

### 1.3 指定输出格式（三要素）

1. **产物类型**：Word / Markdown / Excel / PPT / 纯文本（类型决定结构和内容浓度）。
2. **结构骨架**：文档的标题层级、目录、摘要、附录；表格的列数列名汇总行；PPT 页数与每页主题。
3. **呈现风格**：语气正式/轻松、emoji、图标列表、引用块。

- 实操技巧：**给个样板**。一份样板顶一百字描述，是性价比最高的输出格式约束方式。

### 1.4 避免歧义的表述（五类高频歧义词）

1. **人称代词**：「它」「我们」「那边」→ 换成具体角色或名字。
2. **时间词**：「最近」「上次」→ 换成「最近 30 天」「5 月份」、具体文件名。
3. **模糊量词**：「几个」「一些」「差不多」→ 换成具体数字（5 条建议、约 20 位客户、800 字以内）。
4. **主观形容词**：「专业一点」「高级一些」→ 转成可验证规则（如「使用第三人称、避免口语词、引用至少两个数据点」）。
5. **多个目标**：一句话塞多个动作易被省略草率 → 拆成有序步骤，必要时配合 Plan 模式分步执行。

## 2. 附件与上下文引用（五种挂载方式）

> 肌肉记忆：下达任务前先想——完成这件事，WorkBuddy 需要看到什么资料？

### 2.1 本地文件上传

- 操作：新建任务栏「添加文件」按钮或从文件管理器直接拖入；文件名以小卡片显示在任务栏上方。
- 支持格式：Word、Excel、PPT、PDF、Markdown、纯文本、CSV、JSON、代码文件。
- 三类场景：①单文档分析；②多文件汇总（如 23 份客户反馈归类汇总，优势是逐份真正读完）；③对照参考（挂样板模仿结构风格）。
- 两个坑：①文件越多越大，时间和 token 消耗越多，只要一小段就直接贴文本；②扫描件 PDF 文字是图，需先 OCR 转成可选文本的 PDF。

### 2.2 文件夹授权访问

- 本质：把整个文件夹的访问权限交给 WorkBuddy。授权后可在该工作空间内读取和生成文件；**删除、覆盖、执行脚本、写入工作空间外文件**等高风险操作默认要求用户确认。
- 操作：新建任务栏选「添加文件夹」或通过工作空间挂载目录；首次挂载操作系统弹授权窗口，点允许。
- 三类场景：①批量文件整理（几百张图片按日期归类）；②项目级任务（建子目录、生成文档、建索引）；③长期协作（保存成工作空间后任务默认在该目录干活）——走向长期项目的关键开关。
- 安全两条原则：①不授权根目录或整个用户目录，只授权本次任务真正需要的目录；②重要文件先备份（特别是没用 Plan 模式确认时）。

### 2.3 URL 链接

- 操作：链接直接粘进任务描述，或通过附件入口添加 URL；自动抓取网页正文作上下文。
- 三类场景：①参考竞品或行业资料；②引用在线文档（规范、API 文档、README）；③监控类任务（定期读状态页/数据看板做周期性总结）。
- 两个坑：①登录墙（内网、需登录页面访问不到 → 复制内容、截图或用知识库连接器）；②大型页面（正文过大拉长任务时间，只关心一段就复制下来）。

### 2.4 图片或截图上传

- WorkBuddy 支持多模态：能读图里的文字、结构、内容关系。
- 四个推荐场景：①**设计稿**（生成页面描述、组件清单、代码框架）；②**报错截图**（分析原因、排查建议，比打字快 10 倍）；③**聊天截图**（整理成结构化需求清单/待办）；④**表格截图**（识别转成 Markdown 表格或 Excel）。
- 一个坑：**分辨率**。保留原图分辨率，不拍照、不二次压缩；手机拍屏幕识别率大打折扣。
- 加分技巧：**一张图配一句指令**（如「分析这张报错截图，给出排查思路」）。

### 2.5 腾讯文档、ima 等知识库（连接器机制）

- **腾讯文档**：贴链接或通过连接器授权访问指定文件夹；与普通 URL 不同，连接器**保留文档结构**（多 sheet、多 tab、表格关系）。
- **ima 知识库**：腾讯推出的 AI 知识库产品；WorkBuddy 通过连接器把整个知识库当上下文，基于团队全量知识作答。
- 三类场景：①团队规范引用；②跨项目复用（老项目方案、踩坑记录、复盘文档）；③团队级问答（新人入职、跨团队对接的 AI 答疑助手）。
- 分寸感：知识库范围越大，当次任务上下文负担越重，按需挑选，不无脑挂整个知识库。

## 3. 任务对话与追问技巧（四件套）

### 3.1 持续追问的上下文保持

- 记忆机制：**同一任务对话内，系统自动保留所有前置上下文与历史记录**（初始描述、挂载上下文、历次回复、每次追问）。
- 追问优势：只需明确改什么，无需重复描述做什么。
- 两个边界：
  - **跨任务间不共享上下文**：想把 A 的结果作为 B 的起点，要么把 A 的产物挂为上下文，要么在 A 里继续追问。
  - **长对话稀释注意力**：几十轮后早期内容被压缩概括、细节丢失；建议单任务对话控制在 **5~8 轮**以内，超出则基于当前产物新建任务。
- 实操技巧：**固定锚点**——每隔几轮主动重复核心目标（如「再次提醒，最终产物是面向销售老板的周报」），防止注意力跑偏。

### 3.2 修正方向与打断

- **软修正**：对话里追加新一轮指令把方向拉回来；关键是修正点讲具体（哪一段不行、改成什么样），不说「不行，重做」。
- **硬打断**：任务执行中发送按钮变成停止按钮，点一下立刻停止；已生成内容保留，可基于现有部分继续追问。
- 选用口诀：
  - 方向偏、不伤整体 → 软修正，跑完再调；
  - 方向严重错、再跑浪费 token → 硬打断止损；
  - 任务规模大、可能误改文件 → 直接打断，确认无误再继续。

### 3.3 分步确认策略

- 理念：**把不可逆的风险，前置成可讨论的方案**。
- 与 Plan 模式天然契合（先生成计划待确认再执行，关键节点停下确认）；复杂任务直接用 Plan 模式，不硬扛 Craft；Craft 和 Ask 中也可手动实现。
- 三个分步技巧：
  1. **先大纲，后细节**：长文档/复杂报告第一轮只要大纲；
  2. **先样例，后批量**：批量任务先处理 1~2 个样例确认格式规则风格，再处理全部；
  3. **先方案，后实施**：不可逆操作（代码重构、目录调整、批量删除）先列改动清单，同意后再实施。

### 3.4 追问还是新建任务的判断

- 分界线：**任务核心目标是否变化**——没变→继续追问；变了→新建任务（并把上一份产物挂作上下文）。
- 典型场景：改周报结构语气→追问；周报数据改做老板 PPT→新建；23 份客户反馈换 50 份员工反馈→新建（不同数据集）；重写报告中某段→追问。
- 三条经验法则：①对话过长（超过 8 轮未收敛）考虑新建；②目标发散考虑新建；③结果可复用就新建并挂上下文，不在原任务里把产物改没。

## 4. 结果查看与产物交付

### 4.1 结果区四类视图（左对话、右结果区两栏布局）

1. **产物**：查看任务生成的文件和交付物。
2. **工作空间文件**：查看当前工作空间中的文件内容。
3. **变更**：查看本次任务带来的文件修改。
4. **浏览器**：查看网页或可直接打开的结果页面。

- 关键体验：不离开当前任务，边看对话边查结果；建议多标签页来回切换交叉验证，不停留单一视图。

### 4.2 产物视图

- 两部分：产物列表 + 选中产物预览区。
- 可看内容：文档（Word/Markdown/PDF）、表格（Excel/CSV）、PPT、分析报告及各类交付文件。
- 表格预览确认三件事：表头是否正确、数据是否完整、排版格式是否符合预期；文档预览检查版式、标题、正文；均无需先下载。

### 4.3 工作空间文件与变更视图

- 工作空间文件视图：左文件列表/文件树 + 右内容区；用于看完整内容、对照文件关系、检查写入位置。
- 变更视图：涉及**代码、脚本、配置类任务必须逐项核对改动**，确认无误后再执行接受操作——防误改的关键防线，跳过则回滚成本远高于提前检查。

### 4.4 内置浏览器

- 网页、页面原型、本地 Web 应用的最佳查看入口是内置浏览器，不是产物视图。
- 一句话：**写代码做出来的东西，不是看产物文件，而是看内置浏览器**。

### 4.5 产物分享（两个入口）

1. **从产物列表分享**：产物列表下拉框中找到文件，点右上角分享图标——适合多产物中挑一份发。
2. **从内置浏览器分享**：预览产物时点内置浏览器右上角分享图标——适合看着满意顺手发。

- 分享前检查清单（5 项）：①产物完整性（缺页/缺数据/缺图）；②变更是否符合预期（代码/配置任务先看变更视图）；③敏感信息（客户名、价格、内部代号）；④分享方式选择对不对；⑤配一句话说明（如「附件是这周客户反馈分析，重点看第二段」）。
- 交付前自检流程约 2 分钟，避免大部分交付返工。

## 5. 工作空间与任务归档

### 5.1 工作空间的概念

- 公式：**工作空间 = 项目目录 + 任务集合 + 上下文配置**。
- 任务 vs 工作空间：任务是一次对话、一次产出，是瞬时的；工作空间是一组任务的容器，是长期的。任务挂在工作空间下。
- 工作空间 vs 普通文件夹：普通文件夹只装文件；工作空间还装上下文配置（挂载文档、模型、模式、技能开关），下次进来直接复用。
- 三类场景：①单项目长期跟进；②跨任务复用资料（规范、产品介绍、客户清单）；③团队协作（放共享目录/代码仓库）。
- 一句话：**任务管一件事，工作空间管一个项目。**

### 5.2 用工作空间组织任务

- 新建入口：任务列表「工作空间」板块点「新建工作空间」，起名 + 选一个**非软件安装目录**的本地目录。
- 关键细节：**工作空间的目录就是项目根目录**，空间下任务默认在该目录读写文件；按项目粒度选目录，不选过大的目录。
- 任务装进工作空间两条路径：①新建任务时直接选工作空间入口；②已有任务点三个点图标选「保存到工作空间」（会创建包含该任务的工作空间）。
- 保存后可开启多 Agent 同时协作、在任务列表持久保存、随时打开查看。
- 团队仓库玩法：工作空间目录放在 Git、SharePoint 或腾讯文档同步目录下，每人本地打开同一工作空间，产物自动同步，相当于团队共用 AI 工作台。

### 5.3 任务归档与历史回溯

- **归档**：从日常视线收起，内容完整保留；可随时取消归档放回列表，可基于它继续追问、复用产物。
- **删除**：彻底移除，不可恢复。**99% 的情况用归档**。
- 操作：任务列表点归档图标收进已归档；找回路径：**设置 → 数据管理 → 已归档任务**，可彻底删除或取消归档。
- 该归档的三类任务：①已完成且短期不再用；②告一段落的项目任务（批量归档保持列表清爽）；③参考型任务（示例/模板当案例库，做类似任务时取消归档并挂作上下文）。

### 5.4 多任务并行与切换

- 支持多任务并行，任务列表每张卡片状态独立（进行中/待处理/已完成）；切换只需点另一张卡片，对话、上下文、产物、变更全部独立保留。
- 冲突提醒：多任务在同一工作空间读写同一文件可能冲突；建议并行任务分布在不同工作空间或不同文件，**单次并行控制在 3 个左右最稳妥**。
- 两种执行模式：
  - **专注模式**：需要深度思考、来回追问的任务，只开一个；
  - **多线程模式**：批量执行、机械动作的任务，同时跑几个，自己只负责验收。
- 口诀：**脑子要在的任务串行做，脑子不需要在的任务并行做。**

## 易混点速记

| 易混点 | A | B | 区分关键 |
|---|---|---|---|
| 过程式 vs 终点式需求 | 「帮我看看这份合同」 | 「审阅合同，列出对乙方不利条款并给修改建议」 | 描述终点不是路线 |
| 本地文件 vs 文件夹授权 | 单/多文件，最稳的喂料 | 整个目录读写权限，长期项目开关 | 量级不同；文件夹授权有安全风险 |
| 普通 URL vs 腾讯文档连接器 | 只抓网页正文 | 保留多 sheet、多 tab、表格关系 | 是否保留文档结构 |
| 软修正 vs 硬打断 | 对话追加指令，跑完再调 | 点停止按钮立刻止损，已生成内容保留 | 方向偏用软，严重错/可能误改用硬 |
| 追问 vs 新建任务 | 核心目标没变 | 核心目标变了（挂原产物作上下文） | 跨任务不共享上下文；5~8 轮上限 |
| 产物视图 vs 内置浏览器 | 文档/表格/PPT 等交付文件 | 网页、页面原型、本地 Web 应用 | 代码做出来的东西看浏览器 |
| 归档 vs 删除 | 内容完整保留，可取消、可追问 | 彻底移除不可恢复 | 99% 情况用归档 |
| 工作空间 vs 普通文件夹 | 目录+任务集合+上下文配置 | 只装文件 | 配置跟着工作空间走可复用 |
| 专注模式 vs 多线程模式 | 深度思考任务串行 | 批量机械任务并行验收 | 脑子要在串行，不在并行 |
| 长对话稀释 vs 固定锚点 | 几十轮后早期内容被压缩 | 每隔几轮重复核心目标 | 单任务对话控制 5~8 轮 |
