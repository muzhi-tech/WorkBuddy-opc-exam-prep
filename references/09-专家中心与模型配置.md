# 第9课 考点笔记：专家中心与模型配置

> 一句话总纲：专家 = 给 AI 专业领域经验；模型配置 = 选择最合适的大脑。

## 一、专家与专家团的定义

- **专家** = 独立人设 + 方法论 + 工具链。召唤一个专家等于请到该岗位的资深从业者（如法律顾问会用法律术语、引用法条、从合规角度分析）。
- **专家团** = 团长 + 分工 + 协作的多 Agent 团队。团长自动拆解子任务，分配给多个专家 Agent 并行执行，最后整合各成员产出统一交付。
- 适用差异：**单点问题用专家，复杂大任务用专家团**。

### 专家 VS 专家团对比维度

| 维度 | 专家 | 专家团 |
|------|------|--------|
| 架构 | 单 Agent，单兵作战 | Multi-Agent，团队协作 |
| 组成 | 一个独立人设带方法论 | 一个团长 + 多个专家协同 |
| 积分消耗 | 较低 | 单个专家的数倍 |
| 执行方式 | 顺序处理 | 串行或并行执行后再整合 |

## 二、召唤专家与专家团（四步流程）

**打开 → 选择 → 召唤 → 描述任务**

1. **打开**：主页左侧边栏点击「专家」，进入专家中心页面，展示专家和专家团卡片；专家团卡片额外展示团队成员构成。
2. **选择**：看卡片三要点——能力介绍（核心背景经验）、擅长领域（覆盖方向）、任务示例（能解决的问题类型）；同领域多专家需对比（如法律顾问偏咨询、合规审查专家偏审查）。
3. **召唤**：点击「召唤」按钮，首次召唤系统弹出**积分提醒**（专家团消耗是单专家的数倍，确认积分充足）；重要提醒：AI 生成内容仅供参考、不构成决策建议，法律/医疗/财务领域最终判断需人工确认。
4. **描述任务**：进入对话模式后描述任务需求。

### 专家团工作流程（以内容变现商业化专家团为例）

- 团长先确认账号画像（平台、内容形式、商业化经历、变现期望），再拆解任务分工。
- 成员构成：专家团主理人（整体变现策略）、商业化策略专家（变现路径）、CPS 佣金专家（佣金方案）、效果广告专家（广告策略）、商务合作顾问（合作资源）、收益分析师（数据预测和收益模型）。
- 各专家在各自任务窗口并行执行、独立输出分析报告，最终由团长（主 Agent）整合为一份完整方案（含可视化图表和数据支撑）；可在右侧产物中查看各 Agent 执行过程与产物完成情况。

## 三、我的专家：创建专属专家与专家团

- **入口**：左侧边栏「专家」→ 专家中心页面右上角「我的专家」，集中管理已创建的专家和专家团。
- **创建流程**：
  1. 点击「创建专家」按钮，在对话框中输入提示词描述需求；
  2. AI 生成专家创建方案预览（角色设定和能力配置），确认后回复即开始创建；
  3. 创建完成后可在对话中查看详细信息（角色设定、擅长领域、能力清单），并在「我的专家」卡片中管理。
- **更便捷方式**：在已完成的项目中直接输入创建提示词，AI 结合当前项目上下文更精准地沉淀工作经验，创建后立即出现在列表中，下次对话直接召唤。
- 价值：把个人工作经验和行业积累变成可复用的 AI 能力（专家分身）。

## 四、Skill、专家、专家团三者辨析

| 维度 | Skill | 专家 | 专家团 |
|------|-------|------|--------|
| 组成关系 | 单个工具函数 | 独立角色 + 方法论 | 团长 + 多个专家 + 分工 |
| 本质 | 工具能力 | AI 顾问（工具 + 经验） | AI 协作团队 |
| 解决的问题 | 让 AI 做某件事 | 用什么方法做 | 复杂项目如何交付 |
| 适用场景 | 需要工具能力 | 需要专业建议 | 需要项目交付 |
| 积分消耗 | 最低 | 中等 | 最高 |

- **记忆口诀**：Skill = 能力；专家 = 能力 + 经验；专家团 = 多专家 + 协作。
- 场景速选：「帮我转个格式」→ Skill；「帮我从法律角度审合同」→ 专家；「帮我做一套完整营销方案」→ 专家团；「不知道做什么」→ 灵感（第6章）。

## 五、Multi-Agent 协作架构

- **Agent**：会主动干活的 AI 员工——自己决定下一步、主动调用工具，直到任务完成（区别于普通对话 AI 只回答问题）。
- **Multi-Agent**：多个 Agent 组成团队，各司其职，协作完成复杂任务。

### 协作流程 5 步

1. 用户描述高层次目标；
2. 团长理解需求，拆解为子任务；
3. 团长将子任务分配给合适的专家 Agent；
4. 各专家 Agent 并行或串行执行各自子任务；
5. 团长收集各 Agent 输出，检查一致性，整合为最终交付物。

- 关键优势：「一个人做」VS「一个团队做」。

## 六、标准推理 VS 深度思考（Thinking）模式

| 维度 | 标准推理 | 深度思考（Thinking） |
|------|----------|----------------------|
| 机制 | 直接生成回答 | 先内部推理链（Chain of Thought）再输出结论 |
| 速度 / 消耗 | 速度快、Token 消耗低 | 推理时间更长、Token 消耗更高 |
| 适用 | 日常对话、简单任务 | 复杂逻辑、数学计算、代码调试（准确率显著提升） |

- WorkBuddy 标记：模型列表中标记为**推理模型**的支持 Thinking 模式。
- 选择建议：简单任务用 Auto 标准模型；复杂逻辑分析用推理模型（如**混元 T1 Preview**）。

## 七、内置模型与自动模式

- **自动模式（Auto）**：WorkBuddy 根据任务智能匹配最合适的模型，大部分用户用 Auto 就够了。
- **内置模型**：腾讯混元、智谱 GLM、MiniMax、月之暗面 Kimi、DeepSeek 等主流大模型；各模型能力各有侧重（推理、多模态等），可在模型选择列表查看详细介绍和适用场景。

### 模型选择策略（四类典型决策）

| 场景 | 选择 | 理由 |
|------|------|------|
| 日常对话 | 自动模式 Auto | 智能匹配 |
| 复杂推理 | 混元 T1 Preview | 混元系列推理能力更强 |
| 多模态场景 | GLM 系列或 Kimi 系列 | 图片理解能力强 |
| Agent 场景（频繁工具调用） | GLM 系列或 MiniMax 系列 | 工具调用最稳定 |

## 八、自定义模型：四种接入方式

### 可视化管理界面（公共基础）

- 入口：**设置页 → 模型**，图形界面管理，无需手动编辑配置文件；保存即生效，配置自动持久化。
- 能力标记自动写入（工具调用、图片输入等自动识别）；对话模型选择器自动展示自定义分组；兼容旧配置 model.json（老用户无需迁移）。
- 管理操作：列表展示已配置模型（模型名称 + 供应商图标），支持增删改。

### 方式一：Token Plan

1. 自定义模型配置中选择「腾讯云 Token Plan」；
2. 用腾讯云账号体系完成鉴权和计费，统一入口；
3. 接入后可使用混元、MiniMax、Kimi、GLM 等多个模型；
4. 工具调用、图片输入等能力标记自动识别。
- 特点：**按 Token 用量计费**，适合团队使用；腾讯云统一账号鉴权，无需单独管理每家厂商 API key。

### 方式二：Coding Plan

- 适合 **AI Coding 专项使用**，选对应的订阅方案即可。

### 方式三：自定义 API（一键接入）

1. 从提供商列表直接选择厂商；
2. URL 地址、模型列表、能力标记全部自动填充；
3. 只需补一个 API key 即可保存使用；
4. 全程不需要手动修改任何配置文件。
- 特点：零门槛，面向非技术用户；支持主流厂商预设配置；**其他厂商自定义模型目前仅支持 OpenAI 兼容协议 API**。

### 方式四：Ollama 本地部署

1. 本地安装并启动 Ollama（默认监听 **11434** 端口）；
2. 在 WorkBuddy 模型配置里选择 Ollama 作为提供商；
3. 系统自动通过兼容 OpenAI 协议的接口对接，无需额外配置；
4. 适合政企内网、机舱离线等场景。
- 核心优势：**数据不出本机**——推理在本地 GPU/CPU 完成，零成本、离线可用、隐私有保障。

### 四种方式选型

| 方式 | 适用场景 | 关键操作 |
|------|----------|----------|
| Token Plan | 按量计费的团队 | 选腾讯云鉴权 |
| Coding Plan | AI Coding 专项 | 选对应订阅方案 |
| 自定义 API | 想用特定厂商模型 | 选厂商 + 填 API Key |
| Ollama | 隐私要求高、内网/离线 | 本地安装后选 Ollama |

- **选型口诀**：不知道选啥用 Auto；团队按量计费选 Token Plan；指定厂商用自定义 API；隐私优先用 Ollama。

## 九、最佳实践（5 条）

1. 优先 Auto：不知道选什么时让 WorkBuddy 自动匹配；
2. 能力标记：选标准供应商时系统自动写入，无需手填；
3. Ollama 离线：飞机、内网、敏感场景的不二之选；
4. 自定义协议：非标 URL、网关代理需开自定义协议开关；
5. API key 严管：不泄漏、不提交代码库、定期轮换。

## 易混点速记

| 易混点 | 关键区分 |
|--------|----------|
| 专家 VS 专家团 | 单 Agent 顺序处理、积分低 VS 多 Agent 并行/串行+整合、积分为单专家数倍 |
| Skill VS 专家 VS 专家团 | 能力（做事）VS 能力+经验（怎么做）VS 多专家+协作（项目交付）；积分递增 |
| 团长（主 Agent）职责 | 确认画像 → 拆解任务 → 分配子任务 → 收集检查 → 整合交付 |
| 标准推理 VS Thinking | 直接回答、快、低耗 VS 先 CoT 推理链、慢、高耗、复杂任务准确率高 |
| 混元 T1 Preview | 推理模型，用于复杂逻辑分析，不是多模态首选 |
| 多模态 VS Agent 场景选模 | 多模态选 GLM/Kimi；Agent 工具调用选 GLM/MiniMax |
| Token Plan VS 自定义 API | 腾讯云统一账号按量计费、无需各家 key VS 指定厂商、只需填 API key、URL 自动填充 |
| 自定义 API 协议限制 | 其他厂商仅支持 OpenAI 兼容协议 API |
| Ollama | 本地部署、默认 11434 端口、兼容 OpenAI 协议对接、数据不出本机 |
| 自动模式 Auto | 按任务智能匹配模型，日常对话与「不知道选啥」的首选 |
